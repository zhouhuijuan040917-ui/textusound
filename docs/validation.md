## 已执行的测试

- Node 数据模型测试：四题顺序与稳定 ID、重复词条多来源、批量词汇解析、文本哈希、错误备份关联与格式拒绝。
- 浏览器基础流程：四题 Session、多回答、正文选区提取、词条高亮、跨科去重与多例句、主题修改联动、两类 Writing 保存、Listening 上传音频持久化、播放进度/循环/速度、原始文件下载、Review 翻卡/状态/例句模式、跨科正文搜索、无效备份拒绝、删除材料保留词汇、完整备份恢复、移动端无横向溢出。
- 真实 Kokoro：四道英文面试题和每题第一篇回答、表达 `exchange ideas`、单词 `opportunity`。校验生成的 WAV 格式、24 kHz 采样率、有效时长、下载结果；新标签页重新打开音频后实际解码和播放进度正常；相同内容/声线/语速命中缓存而不新增记录；修改文本后显示旧版本音频警告。
- 模型网络：`huggingface.co` 配置、分词器、模型与音色下载成功；量化 ONNX 和音色资源重定向至 `us.aws.cdn.hf.co`，运行时来自 `cdn.jsdelivr.net`。测试未出现模型下载 403 或 CSP 阻止。当前云环境网络策略为已生效 unrestricted；无需为本轮已访问资源额外放行域名。
- 原版对照：英文题目 3.1 秒 WAV（148,844 字节），回答 11.555 秒（554,684 字节），单词 1.6 秒（76,844 字节）；三份均有非零 PCM、可解码和前进的播放时间。原版刷新丢失音频，新版已用音频 Blob 持久化补足。

## 云端自动测试不能证明什么

- Headless Chromium 可以证明音频解码、非零时长、`paused=false` 和 `currentTime` 前进，但无法替代人耳确认发音、语调或本机扬声器实际出声。
- 自动测试使用浏览器下载事件实际读取文件，未把 mocked 文件选择器当作原生保存验证。**Save as… 的系统对话框、用户授权、取消和记忆目录仍需真实 Chrome/Edge 手动测试**。
- 未在 Firefox、Safari、iOS 或物理手机上实测。响应式布局在 Chromium 390px 宽度验证。
- GitHub Pages 子路径在本地生产静态服务器验证；这不等于已部署到远端。实际 Actions 运行和 Pages 网址须在 PR 合并后确认。
- 不提供付费 AI、自动出题/评分、语音转写、逐词音画对齐、云同步或复杂间隔重复算法。

## 数据与使用限制

- 使用当前浏览器网站存储，容量由浏览器决定，持久存储请求可能不获批准。请导出包含音频的备份；清除站点数据会删除资料。
- 备份导入上限 100 MB，JSON/Base64 导出会消耗内存；不适合未经整理地存放大量长录音。第一阶段没有流式归档或后台数据库。
- 文本仍可编辑，旧音频会明确保留为旧版本；原始录音与合成语音始终分开。
- 首次模型下载需联网。不同设备需手动导入备份，不会自动共享数据。以单一活跃编辑标签页为建议工作方式，未测试并发编辑冲突合并。

真实浏览器逐步验收指南见 [README](../README.md#network-and-browser-checks)。
